Security Findings

P0 wrangler.toml not gitignored wrangler.toml
wrangler.toml contains a hardcoded KV namespace ID (1be5c56c6a374a0fa10c793dc0fdd648) and an ADMIN_SECRET field. The file is not listed in .gitignore. If real credentials are inserted and committed, Cloudflare infrastructure details leak to the public repo.
Add to .gitignore:
# wrangler config
/wrangler.toml

And keep wrangler.toml.example in the repo instead.
P1 KV counter race condition src/workers/waitlist.js:88-90
Cloudflare Workers KV is eventually consistent. Two concurrent signups can read the same count, both increment to N+1, and both write N+1 — losing one signup. KV does not support atomic increments.
Use Durable Objects for atomic counters, or use a SQLite-backed D1 binding with INSERT ... RETURNING. For a quick fix: accept the race (minor) but document the limitation. A Durable Object is ~10 LoC.
P1 No rate limiting on waitlist API src/workers/waitlist.js
Any actor can POST thousands of emails per second to the waitlist endpoint. No rate limiting, no CAPTCHA, no proof-of-work.
Add IP-based rate limiting using Cloudflare's built-in rate limiting API or check request.cf?.country and throttle per-IP. A simple approach: store timestamps per IP in KV with a TTL.
P2 No AbortController on fetch calls src/components/landing/WaitlistSection.tsx:22,56
Both useEffect fetch (count) and submit handler fetch can fire callbacks on unmounted components. No AbortController is used, so .then() callbacks run even after the component unmounts.
Add AbortController to the useEffect:
const abort = new AbortController();
fetch(url, { signal: abort.signal });
return () => abort.abort();
P2 Weak email validation src/workers/waitlist.js:54
Validation !email.includes('@') || !email.includes('.') rejects valid emails like user@localhost and accepts invalid ones like @.com. No normalization (trim, lowercase).
Use a simple regex: /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email.trim().toLowerCase())

Code Quality Findings

P1 useEffect cleanup never fires src/components/landing/WaitlistSection.tsx:31-32
The return () => controls.stop() is inside the .then() callback, creating a new function that is thrown away. The effect itself returns undefined, so React never calls controls.stop() on unmount. The animation continues running, calling setDisplayCount on an unmounted component.
```tsx useEffect(() => { const abort = new AbortController(); fetch(wl.count_endpoint, { signal: abort.signal }) .then(r => r.json()) .then(data => { setCount(data.count); const controls = animate(wl.baseline_count, data.count, { duration: 1, ease: [0.16, 1, 0.3, 1], onUpdate: (v) => setDisplayCount(Math.round(v)), }); // Store controls for cleanup (window as any).__animControls = controls; }) .catch(() => { ... }); return () => { abort.abort(); (window as any)?.__animControls?.stop(); }; }, []); ```
P1 Three.js GPU memory leak src/components/HeroScene.tsx:139-145
The effect cleanup calls renderer.dispose() but never calls geometry.dispose() or material.dispose(). Every mount/unmount of this component leaks GPU buffers (IcosahedronGeometry with subdivision 64 = ~60K triangles of vertex data plus shader program).
```tsx return () => { cancelAnimationFrame(frameId); window.removeEventListener("resize", handleResize); window.removeEventListener("mousemove", handleMouseMove); geometry.dispose(); material.dispose(); renderer.dispose(); if (currentMount.contains(renderer.domElement)) currentMount.removeChild(renderer.domElement); }; ```
P2 DocsPage: 638-line monolith with type unsafety src/components/docs/DocsPage.tsx
This file is a single component with 16 sub-components, all docData.* accesses are typed as any (cast via as unknown as JsonObject & {...}). 15+ any type annotations throughout. If sak-docs.json changes structure, the build succeeds and runtime errors appear. The file imports ../../index.css as a side-effect.
1. Split into separate files per page type (e.g., docs/pages/OverviewPage.tsx).
2. Generate TypeScript types from the JSON schema or use zod for runtime validation.
3. Remove side-effect CSS import — use the global stylesheet instead.
P2 Footer newsletter collects email but never sends src/components/landing/Footer.tsx:93
The newsletter form has onSubmit={(e) => e.preventDefault()} — it collects an email into state (setEmail) but never sends it anywhere. The email is set but nothing consumes it. Dead feature that creates a false sense of signup.
Either wire it to the same waitlist API endpoint used by WaitlistSection, or remove the form and replace with a static "Coming Soon" message.
P2 Team photos decoupled from data src/components/landing/TeamSection.tsx:55
The PHOTOS array is hardcoded separately from team.members in content.json. Reordering, adding, or removing a member in content.json without updating PHOTOS shows the wrong photos.
Add a photo field to each team member in content.json, or use initials-based avatar fallback consistently.
P2 Social icon fallback incorrectly assumes Twitter src/components/landing/TeamSection.tsx:89
The icon map platform === "linkedin" ? <Linkedin /> : <Twitter /> renders a Twitter icon for any non-LinkedIn platform (GitHub, website, Discord, etc.).
```tsx const ICONS: Record = { linkedin: , twitter: , github: , }; const icon = ICONS[platform] ?? ; ```
P3 Unused import in Footer src/components/landing/Footer.tsx:2
Linkedin is imported from lucide-react but never used — the SOCIAL array doesn't include LinkedIn.
Remove Linkedin from the import statement.
P3 Unused import in build.ts build.ts:4
The async cp is imported from fs/promises but only the sync cpSync from fs is used.
Remove the unused cp import.
P3 Large commented dead code block src/components/landing/IncidentSection.tsx:125-143
Approximately 19 lines of commented-out urgency_block JSX. Dead code should be removed, not commented.
Delete the commented block entirely.

Performance Findings

P2 940KB JS bundle includes Three.js + Framer Motion dist/chunk-z1py3n1d.js
The production JS bundle is 940KB. Three.js (@react-three/fiber, @react-three/drei, three) is bundled via HeroScene.tsx which renders an animated 3D icosahedron on the landing page. This adds significant weight for a decorative effect. Framer Motion is used across multiple sections.
1. Lazy-load HeroScene with React.lazy() + Suspense so Three.js is only loaded after initial paint.
2. Consider replacing the Three.js hero with CSS/SVG animations if the 3D effect isn't critical brand IP.
P3 Mousemove handler runs expensive math per event src/components/HeroScene.tsx:124-135
Every mousemove event creates new THREE.Vector3, runs unproject, vector math, and uniform updates. Not throttled.
Throttle the handler: const throttled = (e: MouseEvent) => requestAnimationFrame(() => handleMouseMove(e));
P3 Blur filter animation causes paint jank src/components/docs/DocsPage.tsx:202-204
Animating CSS filter: blur() triggers paint on every frame. On mid-range devices this causes visible jank during page transitions.
Remove filter from the framer-motion initial/animate props. Stick to opacity and y which are composited on the GPU.

Accessibility Findings

P2 No keyboard focus management in mobile menu src/components/landing/Navbar.tsx
When the mobile hamburger menu opens, keyboard focus can tab outside the menu (to background interactive elements). No aria-expanded or aria-controls on the hamburger button.
Add focus trapping: on mount, focus the first menu item; on menu close, return focus to the hamburger. Add aria-expanded and aria-controls to the toggle button.
P3 Nav logo lacks width/height attributes src/components/landing/Navbar.tsx
The brand logo <img src="/final_logo_full_name.png" /> has no width/height attributes, causing layout shift during load.
Add explicit dimensions: width={...} height={...} matching the intrinsic aspect ratio.
P3 Incident cards lack focus indicators src/components/landing/IncidentSection.tsx:114
Incident cards are wrapped in <a> tags but have no visible focus ring for keyboard navigation.
Add Tailwind focus-visible:ring-2 focus-visible:ring-green-400 to the card links.
P3 Three.js canvas missing accessible label src/components/HeroScene.tsx
The WebGL canvas rendered by Three.js has no role="img" or aria-label, making it invisible to screen readers.
Set aria-label on the canvas element to describe the generative art.

Architecture & Maintainability

P2 Hardcoded external URLs in content.json src/content.json:476-477
The waitlist API endpoint and count endpoint are hardcoded URLs. These differ between dev/staging/production but there's no environment-based configuration.
Use environment variables or a config that can vary per-deployment. Or serve from relative paths through the Bun server to avoid CORS entirely.
P2 Hardcoded KV BASELINE in worker src/workers/waitlist.js:7
const BASELINE = 79 requires a code deployment to change. Should be stored in KV so non-technical team members can update it.
Store BASELINE in KV: const BASELINE = parseInt(await env.SAK_WAITLIST.get('baseline') ?? '0');
P3 Route-based URL construction uses # anchors src/content.json:13-14
Routes like "login": "#login" and "launchPlatform": "#waitlist-form" are anchor-based SPA links. The docs page at /docs also uses hash routing internally. This creates duplication between the Bun server's catch-all route and the client-side routing.
Consider using a proper client-side router (react-router) if the app grows beyond a single landing page. For now, document the routing convention clearly.
